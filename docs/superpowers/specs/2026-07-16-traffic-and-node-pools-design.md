# 流量监控与节点池设计

**日期：** 2026-07-16
**状态：** 已批准，进入实现

## 目标

在不让 FastAPI/Python 进入代理转发数据路径的前提下，为现有固定端口代理管理器新增：

1. 可持续保存的上下行流量统计，按监控总览、端口、节点池和节点下钻。
2. 可公开访问的节点池端口，支持健康成员的普通轮询、加权轮询、手动前进、成员排空和连接前故障跳过。
3. 以“监控”作为第一个主导航，承载总览、趋势、明细和事件；节点池作为“运行”页的二级视图。

现有固定端口的节点绑定、HTTP/SOCKS5 混合入站、导入、测速、端口验证和管理 API 必须保持可用。

## 范围与边界

- 固定端口保持静态出口，不会被节点池覆盖或重写。
- 节点池在每条新的 **TCP** 连接建立前选择成员；已建立会话永不迁移或强制切换。
- 节点池支持 HTTP 代理和 SOCKS5 TCP 隧道。SOCKS5 UDP 保留在现有固定端口，后续单独设计。
- 不记录目标 URL、请求内容、认证凭据或客户端 IP。监控只记录字节、连接数、健康与运行事件。
- 管理面可以查询统计/控制 Router；代理字节始终经过 Go Router 与 sing-box，不经过 Python。

## 架构

### 固定端口

```text
应用 -> :8001 mixed inbound -> route -> node-A outbound
```

生成的每个固定 sing-box 入站使用 `port-{port}` 标签。sing-box V2Ray Stats API 按该标签报告上下行累计字节和活跃连接。

### 节点池

```text
应用 -> :8201 pool-router -> 127.0.0.1:18xxx pool-member inbound -> route -> node outbound
```

- `pool-router` 是扩展现有 `proxycheck-api` Go module 的独立二进制，管理进程随 sing-box 一起启动/停止。
- 每个池成员拥有只监听 loopback 的 sing-box `pool-member-{pool}-{node}` 入站；同一节点可同时供固定端口和多个池复用。
- Router 在接受连接后、转发任何业务字节前，选择可用成员并连接其内部端口。内部连接失败时尝试下一个成员；一旦桥接开始，错误只关闭该会话。
- 策略包括 `round_robin` 与 `weighted_round_robin`（默认）。权重为 1–100；全部为 1 时两种策略结果相同。
- 成员状态为 `active`、`draining`、`unhealthy`。`draining` 不接收新连接但不影响旧会话；健康失败和 Router 拨号失败进入带退避的 `unhealthy`。
- “切换下一节点”只移动下一次选择的游标，不影响活跃会话。

## 状态与存储

### assignments.json

在现有 `AppState` 中持久化池配置：

- `pools`: `id`、名称、公开监听端口、策略、启用状态、成员列表、创建/修改时间。
- 每个成员: `node_tag`、`weight`、`enabled`、`draining`。

节点删除或替换时会同步移除/禁用无效池成员；空池不可启动。

### traffic.db

新增独立 SQLite 数据库，不把时序数据写入 `assignments.json`。

- `counter_cursor` 保存各统计源的上次累计计数与采样时间，处理引擎重启造成的计数回退。
- `traffic_bucket` 存储按分钟的上行、下行、连接增量和活跃连接峰值，维度为 `port`、`pool` 和 `node`。
- `traffic_event` 存储不会暴露请求内容的操作事件：引擎启动/停止、成员健康变化、成员排空、手动前进、Router 拨号失败。
- 采样间隔 15 秒，写入所属分钟桶；保留 48 小时分钟桶、90 天小时桶、365 天日桶。降采样与清理由后台任务在低负载时执行。

以“客户端 → 目标”为**上传**，以“目标 → 客户端”为**下载**。所有页面都使用完整文字和颜色以免仅靠颜色区分。

## 统计采集

1. 生成器启用 sing-box V2Ray Stats API，对固定入站和池成员入站登记统计。
2. FastAPI 生命周期任务每 15 秒读取累计字节与活跃连接，按入站标签归类并计算正向 delta。
3. Router 提供只绑定 `127.0.0.1` 的状态端点，汇报池监听端口的上下行、活跃会话、选择次数和拨号失败；FastAPI 同步入库。
4. 原始计数回退（重启/重载）时不产生负流量，重置 cursor 并记录一次引擎事件。
5. API 查询按所选时间范围自动选择分钟/小时/日桶；当前速率使用最近 60 秒窗口。

## API

### 节点池

- `GET /api/pools`：池列表、当前成员健康、实时 Router 统计和可复制 HTTP/SOCKS 地址。
- `POST /api/pools`：创建池。
- `PUT /api/pools/{pool_id}`：更新名称、端口、策略和成员；必要时安全重载引擎/Router。
- `POST /api/pools/{pool_id}/advance`：推进下一次选择游标。
- `POST /api/pools/{pool_id}/members/{node_tag}/drain`：切换排空状态。
- `POST /api/pools/{pool_id}/check`：对成员发起健康检查。
- `DELETE /api/pools/{pool_id}`：删除池并停止其监听。

### 流量与事件

- `GET /api/traffic/overview?range=24h`：总计、当前速率、活跃连接、异常摘要及时间序列。
- `GET /api/traffic/entities?range=24h&type=port|pool|node`：可筛选、排序的明细列表。
- `GET /api/traffic/entities/{type}/{id}?range=24h`：详情抽屉的趋势、摘要及关联成员。
- `GET /api/traffic/events?limit=100&entity_type=&entity_id=`：安全的操作/健康事件。

## 前端

### 主导航

`监控`（新、默认） → `节点` → `分配` → `运行`。

“运行”保留引擎、版本、自检、AI 连通性和端口验证，增加二级 tab：`引擎与诊断` / `节点池`。

### 监控页

- 顶部时间范围 1h/24h/7d/30d；当前范围在 URL/本地存储中保存。
- 指标卡：下载、上传、当前上下行速率、活跃连接、需处理异常。每个数值有可读标签与环比/状态文本。
- 无外部图表依赖，采用带 `<title>`、图例、键盘可访问说明和数据表后备的 SVG 双折线图。
- 端口/节点/池明细表支持类型、健康、上下行、活跃连接、最后活动、排序和搜索。
- 点击行打开侧边详情抽屉，显示该实体的趋势、成员/固定映射信息和不含请求内容的事件。

### 节点池页

- 列表显示名称、端口、策略、可用成员/总成员、实时连接、今日流量、健康。
- 编辑抽屉包含池端口、策略、成员选择、权重、启用/排空状态和明确的保存/校验反馈。
- 对当前可用成员显示“下一顺序”预览；操作包括复制代理地址、检查、前进、排空和删除。
- 交互提供加载、空、错误、禁用和键盘焦点状态；动画仅使用 150–300 ms 的 transform/opacity，并尊重 `prefers-reduced-motion`。

## 错误处理

- Router 二进制不存在、配置解析失败、端口冲突、空池、重复端口和非存活成员均在保存前报告可操作错误。
- 统计 API 无法连接不会影响代理；监控显示“暂不可用”及最后成功采样时间，并自动重试。
- Pool Router 失败时状态标红；固定端口继续正常运行。
- 所有配置变更在引擎重载失败时保留旧配置和明确错误，不写入半完成状态。
